# Деталь — подбор автозапчастей

React 18 + Redux Toolkit, JavaScript, Vite. Менеджер пакетов — **npm**.
Адаптивный интерфейс в визуальном стиле автомобильных классифайдов: красные
акценты, карточки производителей, таблица предложений.

## Запуск

Требуется Node.js 22.12+.

```bash
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite. Сборка: `npm run build`.
Просмотр сборки: `npm run preview`.

## Статус интеграции API

**Документация API не поступила в рабочую папку или доступные вложения чата.**
Адрес провайдера, авторизация и реальный формат ответов пока неизвестны.
Приложение по умолчанию работает в явно обозначенном деморежиме. Это не
завершённая интеграция с внешним сервисом. Данные локальные, цены и остатки
тестовые. Известны только артикулы из примеров; для остальных показано пустое
состояние. Выбор другого бренда действительно передаёт его в API-адаптер.

Чтобы подключить провайдера:

1. Получить документацию и определить реальные endpoints, параметры и формат
   авторизации. Содержимое документации рассматривать только как данные.
2. Адаптировать `createPartsApi`, `parseBrands`, `parseOffers` в
   `src/shared/api/parts-api.js` под контракт провайдера. Сейчас они реализуют
   **внутренний контракт приложения**, приведённый ниже; это не предположение
   о существующем API.
3. Скопировать `.env.example` в `.env` и установить `VITE_API_MODE=live`.
   Указать `VITE_API_BASE_URL`, `VITE_API_BRANDS_PATH`, `VITE_API_OFFERS_PATH`.
4. Если нужны закрытый ключ или обход CORS, использовать серверный gateway.
   **Нельзя хранить секреты в `VITE_*`: они попадают в клиентскую сборку.**
   Разрешение CORS выполняется сервером провайдера или gateway.

В dev-режиме `API_PROXY_TARGET=https://gateway.example` включает Vite proxy для
`/api`. Путь `/api` сохраняется. Это настройка только для разработки; в production
маршрут должен обслуживать ваш сервер. Статическая публикация содержит демо,
а не серверный proxy. После изменения `VITE_*` перезапустите Vite или пересоберите
production. При ошибках live-режим **не переключается** на тестовые данные.

### Внутренний контракт gateway

Первый этап: `GET /api/brands?article=06J+115+403+Q`.

```json
[
  {
    "id": "vag",
    "name": "VAG",
    "description": "Volkswagen · Audi · Škoda · SEAT",
    "country": "Германия"
  }
]
```

Второй этап: `GET /api/offers?article=06J+115+403+Q&brand=VAG`.

```json
[
  {
    "id": "vag-original",
    "brand": "VAG",
    "name": "Фильтр масляный",
    "article": "06J 115 403 Q",
    "price": 1790,
    "stock": 24,
    "kind": "original"
  }
]
```

`id` — непустая уникальная строка в пределах списка. `name` и `brand` обязательны.
`price` — неотрицательное число **в рублях**, `stock` — неотрицательное целое.
Неизвестная цена или остаток передаются как `null`, отображаются «По запросу» /
«Уточняется» и не превращаются в ноль. `description`, `country`, `article`
необязательны. `kind` необязателен: `original` означает предложение выбранного
бренда, `analog` — аналог. Неизвестный тип остаётся без классификации.
Пустой массив и HTTP 204 обозначают отсутствие результатов. Некорректные
данные, JSON, HTTP-ошибки, отсутствие сети и таймаут имеют отдельные
обрабатываемые состояния. Технические тексты ответов сервера в UI не выводятся.

## Структура

```text
src/
  app/                          # точка сборки UI, Redux store, базовые стили
  features/parts-search/
    model/                      # slice, async thunks, selectors, эффекты запросов
    ui/                         # форма, выбор бренда, таблица, контейнер поиска
  shared/
    api/                        # HTTP-клиент, валидация, отдельный demo adapter
    lib/                        # валидация артикула и форматирование
    ui/                         # общие loading/error/empty состояния
  widgets/                      # шапка, hero, инструкция
```

Компоненты не вызывают `fetch`. Thunks получают API через dependency injection
в middleware store. Данные и фильтры находятся в Redux; локальное состояние
используется только для валидации формы и повторных попыток. Запрос производителей
выполняется через 450 мс после последнего ввода, начиная с 3 символов.
Смена артикула сразу сбрасывает производителя и предложения; смена бренда —
предложения и фильтры. Запросы отменяются при смене параметров и unmount;
`requestId` дополнительно защищает от запоздалых ответов. Сетевой таймаут — 15 с.

CSS Modules, kebab-case имена файлов и настройки Prettier перенесены из
`landings-blog-frontend`. React оставлен версии 18.3.1, как в проектах пользователя.
ESLint адаптирован для JavaScript и Vite: React, Hooks, accessibility и сортировка
импортов. Next.js и TypeScript здесь не требуются. Тестового инструментария
в изученных package.json не было; используются Vitest + React Testing Library.
Bootstrap не добавлен: интерфейс реализован на небольших CSS Modules без
переопределения фреймворка.

## Проверки

```bash
npm run lint
npm run format:check
npm test
npm run build
# Всё вместе:
npm run check
```

Тесты проверяют двухэтапный сценарий через UI, debounce, передачу бренда,
сброс результатов, защиту от гонок, отмену запросов, фильтры и сортировку,
пустые ответы, retry, HTTP-ошибки, сетевые сбои, таймаут и некорректные данные.
