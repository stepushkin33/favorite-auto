# Деталь — подбор автозапчастей

React 18 + Redux Toolkit, JavaScript, Vite, npm. Адаптивный интерфейс поиска
производителей, оригинальных деталей, аналогов и складских предложений.

## Запуск с реальным API

Требуется Node.js 22.12+.

```bash
npm ci
cp .env.example .env
# Указать свой FAVORIT_API_KEY в .env.
npm run dev
```

Если `.env` уже настроен, не перезаписывайте его командой копирования.
Откройте адрес Vite. Сервер разработки обслуживает `/api/parts` и добавляет
ключ покупателя к запросам Favorit Parts. Сам ключ не попадает в браузер.
Для проверки можно использовать артикул `01089` из документации.

Деморежим включается явно и не делает запросов к поставщику:

```bash
npm run dev:demo
```

В live-режиме нет скрытого переключения на демоданные при ошибках.

## Контракт Favorit Parts

Адаптер реализован по предоставленному `wsprice (1).pdf`, «Проценка»,
редакция от 06.03.2023. Endpoint: `/hs/hsprice/` на `api.favorit-parts.ru`.
В PDF приведён HTTP-адрес; приложение использует тот же endpoint по HTTPS.
Два реальных запроса через HTTPS с предоставленным ключом прошли успешно.

1. Производители: `GET /api/parts?number=01089`.
   Прокси передаёт `key` и `number`; клиент извлекает уникальные бренды из `goods`.
2. Предложения: `GET /api/parts?number=01089&brand=OSSCA&analogues=on&info=on`.
   Прокси передаёт номер, выбранный бренд, `analogues=on`, `info=on` и серверный
   ключ. Клиент обрабатывает основную деталь и вложенный массив `analogues`.

Особенности преобразования:

- Каждая строка — конкретное предложение `goodsID + warehouses[].id`.
- Цена и остаток берутся **из одного склада**: `warehouses[].price` и
  `warehouses[].stock`. Устаревшее `goods.price` никогда не используется.
  Общий `goods.count` не подставляется вместо складского остатка.
- Код склада показывается возле артикула; если кода нет, используется его `id`.
- Основные детали и вложенные аналоги классифицируются по положению в ответе:
  аналог может иметь того же производителя, но другой артикул.
- Повторяющиеся товары и складские предложения удаляются по стабильному ключу.
- При пустом `warehouses` позиция остаётся в списке с ценой «По запросу».
  Нулевой `count` обозначает отсутствие; иначе остаток остаётся неизвестным.
- `null` для цены/остатка отображается «По запросу» / «Уточняется». Ноль остаётся
  нулём. Некорректные типы или отрицательные значения вызывают ошибку данных.
- Ответ `{ "goods": [] }`, HTTP 204 и документированная пустая структура с
  нулевым GUID обрабатываются как отсутствие результатов.
- Ошибки в JSON-поле `error` обрабатываются даже при HTTP 200: пустой/неверный
  ключ, пустой номер, исчерпанная квота. Произвольный текст сервера не выводится.
- `notRefund` товара или склада показывает отметку «Без возврата по отказу».

## Серверный прокси и публикация

Секрет хранится в `FAVORIT_API_KEY` на сервере. Опционально `FAVORIT_API_URL`
задаёт HTTPS endpoint поставщика, `VITE_API_URL` — URL собственного gateway
(по умолчанию `/api/parts`). Клиентские параметры `key`, `url` и другие
неизвестные поля игнорируются. Прокси не следует редиректам, не возвращает
технические тексты поставщика и отдаёт API-ответы с `Cache-Control: no-store`.
Таймаут поставщика — 12 с, клиента — 15 с. Отмена клиентского запроса отменяет
обращение к поставщику.

Обычный Node.js запуск собранной версии:

```bash
npm run build
npm start
```

Сервер читает `.env`, слушает `127.0.0.1:3000` (порт настраивается через `PORT`),
обслуживает клиентскую сборку и тот же gateway. При внешнем развёртывании нужен
обычный reverse proxy. `npm run preview` предназначен только для просмотра
клиентской сборки, без серверного API; для реального поиска используйте `npm start`.

Для Sites сборка также создаёт самостоятельный `dist/server/index.js` с
`default.fetch(request, env)` и встроенными клиентскими ресурсами.
Это тонкий адаптер хостинга, React-приложение остаётся клиентским.
Существующий приватный Site переведён со статической раздачи на Worker;
его идентификатор и аудитория сохранены. `FAVORIT_API_KEY` настроен как secret
в окружении Sites. В `.openai/hosting.json` и исходниках секретов нет.

`.env` исключён из Git. Не помещайте ключ в `VITE_*`, query string браузера,
исходники или скриншоты. Сборка проверяет ESM entrypoint, HTML и API-маршрут
Worker до упаковки. Скрипт публикации использует npm.

## Структура и поведение

```text
src/
  app/                          # UI, Redux store, базовые стили
  features/parts-search/
    model/                      # slice, thunks, selectors, эффекты запросов
    ui/                         # форма, бренды, таблица, фильтры, строка
  shared/
    api/                        # HTTP-клиент, Favorit adapter, demo adapter
    lib/                        # проверка артикула и форматирование
    ui/                         # loading/error/empty состояния
  widgets/                      # шапка, hero, инструкция
server/
  favorit-gateway.js             # общий gateway для Vite, Node.js и Sites
  node-gateway.js                # адаптация Node.js HTTP к Request/Response
  index.js                       # production Node.js сервер
  worker.js                      # адаптер хостинга Sites
scripts/
  build-worker.mjs               # упаковка и проверка Sites Worker
```

Компоненты не вызывают `fetch`; thunks получают API через middleware store.
Поиск производителей выполняется через 450 мс после последнего ввода, начиная
с 3 символов. Смена артикула сбрасывает обе стадии, смена бренда — предложения
и фильтры. Запросы отменяются при смене параметров и unmount; `requestId`
дополнительно защищает от запоздалых ответов. Фильтры и сортировка — в Redux.
На телефоне строки таблицы перестраиваются в карточки с видимой ценой и остатком.

React 18.3.1, CSS Modules, kebab-case и настройки Prettier взяты из предыдущего
`landings-blog-frontend`. ESLint адаптирован под JavaScript/Vite: React, Hooks,
accessibility, сортировка импортов. TypeScript и pnpm не используются.
Тестового инструментария в изученных проектах не было, поэтому выбраны
Vitest и React Testing Library. Bootstrap не добавлен: небольших CSS Modules
достаточно для выбранного дизайна.

## Проверки

```bash
npm run check
# ESLint + Prettier + Vitest + production build и валидация Worker.
```

Тесты проверяют два этапа через UI, debounce, сброс результатов, гонки и отмену,
фильтры, сортировку, складские цены и остатки, вложенные аналоги, неизвестные
значения, ошибки HTTP/JSON, квоту, повторные попытки, таймаут и серверный ключ.
Сетевые обращения в unit/integration тестах замоканы; проверка реального API
выполнялась отдельно, чтобы не тратить квоту при каждом запуске тестов.
